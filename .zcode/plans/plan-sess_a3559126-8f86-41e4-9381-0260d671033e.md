## تصمیمات قضاوت (به‌دلیل پاسخ‌ندادن به سؤالات)

1. **محتوای مارکتینگ → config** (نه lang): پروژه lang/ ندارد ولی `config/ai.php` دارد. الگوی موجود config است. ساخت lang/ فقط برای یک ماژول آزمایشی، معرفی کانوشن سنگین جدید است.
2. **توکن‌های بصری CSS دست‌نخورده**: به Tailwind گره خورده‌اند؛ استخراج به config لایه ابهام غیرضروری می‌سازد و کد را غیرواقعی‌تر می‌کند.
3. **سcaffold مرده حفظ می‌شود** ولی کامنت پاک می‌شود (توازن بین «پاکسازی» و «بدون تغییر رفتار»).
4. **سبک کامنت = الگوی موجود** (`Gif.php`, `UploadGif.php`): PHPDoc فقط روی متدهای عمومی، `// ---` برای جریان غیربدیهی، کامنت کوتاه فارسی/انگلیسی آزاد.
5. **SVG pathها در blade می‌مانند** (markup نمایشی)، فقط label/url/عدد/رشته به config می‌روند.

## تغییرات منطقی کلیدی

- **`Landing.php`**: `latestGifs(8)` → `latestGifs(config('landing.showcase.count'))`؛ حذف `#[Title]` (عنوان از layout با config می‌آید، چون attributeهای PHP نمی‌توانند `config()` صدا بزنند و این تکرار را حذف می‌کند)؛ حذف کامنت ۳‌خطی توضیحی.
- **`layouts/landing.blade.php`**: `<title>` و metaها از `config('landing.seo.*')`؛ حفظ همه CSS tokenها و رفتار انیمیشن؛ حذف کامنت‌های مقاله‌ای (توضیح font/Vite، safe-area، reduced-motion) و نگه‌داشتن فقط هشدارهای ضروری.
- **sectionها**: آرایه‌های `@php` محتوای هاردکد با `config('landing.xxx')` جایگزین می‌شوند؛ markup ساختاری و SVGها باقی می‌مانند.
- **Providers**: حذف `use Schedule` بلااستفاده، حذف بلوک‌های `// protected $commands` و `configureSchedules` کامنت‌شده.
- **رشته‌های تست‌محور** (`Admin Panel`, `Sign in`, `Get Started`, `View all GIFs`) با مقدار دقیقاً یکسان در config قرار می‌گیرند تا تست‌ها پاس شوند.

## طبیعی‌سازی سبک

- حذف: بنرهای ASCII `═══`، یادداشت‌های «Implemented in: Task NN»، کامنت فارسی بلوکی showcase، docblock‌های generic Nwidart.
- حفظ: PHPDoc روی متدهای عمومی، کامنت کوتاه `//` برای جریان غیربدیهی، اجازه کامنت دوزبانه کوتاه.
- بدون type-hint/docblock اضافه؛ بدون نام‌گذاری بیش‌حد توصیفی.

## خروجی نهایی (تحویل پس از اجرا)

1. لیست فایل‌های تغییر یافته
2. جدول: مقدار هاردکد → مقصد جدید → دلیل انتخاب
3. تأیید حذف کامنت‌های غیرضروری
4. جمع‌بندی: آیا همین الگو برای بقیه ماژول‌ها مناسب است یا نیاز به تنظیم دارد

## ریسک‌ها و کنترل
- **رفتار تغییر نکند**: refactoring خالص، حفظ رشته‌ها/مسیرها/اعداد در مقدار نهایی.
- **تست‌ها سبز بمانند**: مقادیر assert‌شده دقیقاً حفظ می‌شوند، تست‌ها دست‌نخورده.
- **CSS دست‌نخورده**: ظاهر صفحه عینی تغییر نمی‌کند.
